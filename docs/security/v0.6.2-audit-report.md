# v0.6.2 安全维护审计报告（S2-G）

> 审计日期：2026-09-07  
> 审计范围：v0.6.2 纯隐私、安全、依赖与供应链维护  
> 审计状态：**有条件通过，尚未达到正式发布批准条件**

## 1. 结论摘要

本次审计确认 v0.6.2 维护变更已经覆盖隐私扫描、IPC 错误边界、设置存储安全、GitHub Actions 权限与 SHA 固定、SBOM/license/checksum 校验，以及 TUI 依赖升级。PR #54 的 GitHub Actions CI 已于 **2026-09-07** 全部通过。

但当前不能批准正式发布，原因是：

1. PR #54 尚未合并到 `dev`，其 Dependabot 修复尚未成为默认分支基线；
2. GitHub Security API 在 **2026-09-07** 仍报告默认分支有 3 个 Dependabot 告警和 4 个 CodeQL 告警，合并后必须重新读取并确认状态；
3. E2E 的 `extract-zip` high 告警仍是已登记的测试工具链风险接受项，复核日期为 **2026-10-06**；
4. `glib 0.18.5` medium/unsound 告警仍按独立风险接受处理，复核日期为 **2026-12-31**；
5. Windows Terminal 原生 TUI 交互回归、Windows 设置安全 artifact 证据和正式预发布演练尚未完成；
6. 按项目规则，尚未获得正式发布批准，因此不创建 `v0.6.2` tag、不构建、不发布。

### 2.3 隐私与安全边界

- 用户正文默认不落盘，`restore_last_input` 关闭时保存前归一化为空；
- 设置写入包含原子替换、备份恢复、Unix `0600`、symlink 拒绝和进程内串行化；
- IPC 使用稳定 `{ code, message }` 错误协议，前端不展示原始内部错误；
- 凭据扫描不会把命中源行或凭据原文写入诊断输出；
- CI job 使用最小 `contents: read` 权限，第三方 Actions 使用固定 commit SHA；
- Release 校验包含动态 notes、`expected_sha`、SBOM、checksum 和许可证清单终验。
