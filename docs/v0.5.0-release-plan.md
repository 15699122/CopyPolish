# CopyPolish `v0.5.0` 正式发布开发计划

本文档是 CopyPolish（文案净排）`v0.5.0` 正式发布前的开发与验收计划。计划基于当前 `dev` 分支、Tauri 2 + React + Rust 架构以及现有 CI / Release 流程制定。

## 1. 发布目标与范围

### 本轮目标

发布 CopyPolish / 文案净排 `v0.5.0` 正式版。

### 本轮优先级

1. 先保证格式化正确性，再扩展功能；
2. 先建立测试基座，再新增规则或大型 UI 功能；
3. 先完成 Windows 真实环境验收，再发布正式版；
4. 所有范围变动先更新本计划和验收标准。

### 本轮不纳入范围

除非发现会阻断 `v0.5.0` 发布的问题，本轮暂不进行：

- 新格式化规则开发；
- 大规模 UI 视觉重设计；
- macOS 支持；
- 安装版或自动更新器；
- 大型编辑器功能，例如文件批处理、项目级规则集和云同步。

## 2. 已确认的关键决策

- 本轮目标版本为正式版 `v0.5.0`。
- 优先解决“全不选”与 Rust 空规则列表之间的语义问题。
- 在黄金样例回归测试体系建立前，不继续新增格式化规则或大型 UI 功能。
- 按本文档的阶段顺序推进开发。
- 本计划在任何代码改动之前同步到仓库 Markdown 文档。

## 4. 阶段 1：修复“全不选”与空规则列表语义 ✅

### 问题

前端“全不选”会生成空规则列表，而 Rust 当前管线把空规则列表解释为“启用全部规则”。必须消除这一双重语义。

### 目标语义

| 用户意图 | 后端语义 |
| --- | --- |
| 全选 | 执行全部已注册规则 |
| 恢复默认 | 执行所有默认启用规则 |
| 自定义选择 | 仅执行指定规则 |
| 全不选 | 不执行任何规则 |

### 实施内容

1. 已审核 `App.tsx`、`lib/tauri.ts`、Tauri command、`FormatRequest` 和 pipeline 的完整调用链；
2. 采用显式 `RuleSelection` 模型，避免依赖空数组表达多个含义；
3. 同步修改 Rust 请求模型、command、pipeline 及前端类型；
4. 保留设置文件中 `enabled: string[]` 的存储结构，其中空数组表示“全不选”；
5. 增加 Rust 和前端测试，覆盖全选、默认、自定义、全不选、未知 key 和恢复流程；
6. 在开发文档中记录最终规则选择 API 约定。

### 验收标准

- [x] 点击“全不选”后，输出与输入完全一致；
- [x] “恢复默认”仅启用注册表中的默认规则；
- [x] 空启用集重启恢复后仍表示“全不选”；
- [x] 不影响浏览器预览和 Tauri 正式运行模式；
- [x] Rust、前端测试与构建全部通过。

## 6. 阶段 3：建立格式化引擎黄金样例回归测试 ✅

### 目标

在继续新增规则或大型 UI 功能前，将规则、保护层、换行和规则选择行为沉淀为数据驱动的回归样例。

### 建议目录

```text
src-tauri/tests/fixtures/
├── spacing.yaml
├── punctuation.yaml
├── markdown.yaml
├── latex.yaml
├── url-email.yaml
├── chemistry.yaml
├── newlines.yaml
├── rule-selection.yaml
└── regressions.yaml
```

### Fixture 最小结构

```yaml
name: 中文与英文之间插入空格
selection:
  mode: only
  keys:
    - spacing.cjk-latin
input: 在LeanCloud上
expected: 在 LeanCloud 上
```

### 覆盖范围

- 12 条现有规则；
- Markdown、LaTeX、URL、邮箱、代码块和化学式保护；
- `LF`、`CRLF`、`CR` 换行；
- emoji 和 CJK 扩展区；
- 全选、默认、指定规则、全不选；
- 规则组合、未知 key 和历史回归问题。

### 回归约定

- 每次修复格式化 bug，必须增加 `regressions.yaml` 案例；
- 每次新增规则，必须增加规则单测和组合案例；
- 每次修改保护层正则，必须补充保护边界案例；
- fixture 预期输出以当前产品规范为准，不机械依赖历史 Python 输出。

### 验收标准

- [x] Rust 测试自动加载并执行全部 fixture；
- [x] 每条规则和每类主要保护类型都有覆盖；
- [x] 四种规则选择模式都有覆盖；
- [x] 失败信息包含 fixture 文件和案例名；
- [x] 回归测试进入 CI 门禁。
