# PDF/CAJ 段内软换行与 CJK 内部空格 Spike

> **状态**：Spike 基线；CJK 内部单空格子集已进入默认关闭的保守试实现，但未经真实 PDF/CAJ 语料和人工标注验收（2026-09-04）。仓库当前没有可提交的真实 PDF/CAJ 原文件或脱敏文本；本记录中的样例均为合成失败基线，不能作为真实来源验收证据。段内软换行、多栏顺序和连字符断词仍未实现。

## 1. 问题范围

用户从 PDF、CAJViewer、Zotero 或网页复制文本后，常见两类候选问题：

1. 同一段落被复制成多行，行尾没有句末标点，却在下一行继续同一句；
2. CJK 字符之间混入来源排版产生的异常空格，例如 `中 文`、`数 据`。

目标不是解析 PDF/CAJ 文件本体，而是对用户粘贴进 GUI/TUI/CLI 的纯文本做可选清洗。

## 2. 当前基线与合成失败案例

以下样例只用于冻结风险，不代表生产规则应当直接得到这些输出：

| 场景 | 合成输入 | 不能直接自动推断的原因 |
| --- | --- | --- |
| 段内软换行 | `这是一个跨行\n继续的句子。` | 换行可能是段落边界、列表边界、双栏顺序错误或真正换行；缺少版面坐标无法判断 |
| 连字符断行 | `inter-\nnational` | 可能是英文断词，也可能是原文中的减号、命令参数或标识符 |
| CJK 单字空格 | `中 文 本` | 可能是 PDF 字符定位误差，也可能是用户刻意分隔、表格列或注音排版 |
| CJK 与标点 | `文 。 本` | 可能需要移除空格，也可能跨越结构边界或属于代码/公式内容 |
| 多栏文本 | `左栏第一行\n右栏第一行\n左栏第二行` | 纯文本已丢失栏位坐标，任何拼接顺序都可能破坏语义 |
| 表格/公式 | `样 品 量\nE = m c 2` | 表格列间距和公式内部空格不能按普通正文规则清理 |

这些失败案例共同说明：**仅凭换行字符和空格字符，无法可靠恢复 PDF/CAJ 的版面结构**。当前实现的 span 扫描器能保护 Markdown、URL、代码、LaTeX、HTML 和已识别语义 token，但不能恢复已经丢失的 PDF 版面坐标。

## 3. 候选规则与保守边界

未来可以评估两个相互独立、默认关闭的规则，而不是一个宽泛清洗器：

### 3.1 段内软换行

只考虑满足全部条件的相邻行：

- 两行均为普通可编辑正文，不属于代码、表格、HTML、LaTeX、URL 或引用结构；
- 前一行没有句末标点、列表标记、标题标记或明显字段分隔符；
- 后一行不是新段落、编号项、英文命令、URL 或公式起始；
- 合并后经过已有格式化规则仍保持幂等；
- 原始换行风格和无法判断的行必须保留。

即使满足这些条件，也只能作为候选启发式，不能声称恢复了原始 PDF 段落。

### 3.2 CJK 内部异常空格

只考虑普通正文中相邻 Han grapheme 之间的单个 ASCII 空格；必须跳过：

- Markdown/HTML/LaTeX/代码/URL/邮箱和表格；
- 多个连续空格、制表符和换行跨越的间隔；
- CJK 与拉丁字母、数字、单位或标点之间的边界；
- 可能表示列分隔、注音、脚注或人工排版的文本。

该规则仍需要真实来源语料证明误删率可接受，不能只靠合成例子宣称完成。当前试实现只删除普通可编辑文本中相邻 Han grapheme 之间的单个 ASCII 空格；连续空格、制表符、跨行间隔、其他脚本/标点边界和受保护结构均保留。

## 4. 进入实现阶段的前置条件

必须先收集经过许可或脱敏的真实文本样本，至少包括：

1. 单栏 PDF 正文，含段落、标题、列表和页眉页脚；
2. 多栏 PDF，记录预期阅读顺序；
3. CAJViewer 复制文本，覆盖中文、英文、数字、公式和表格；
4. 已知应合并、应保留和无法判断的行边界标注；
5. CJK 内部空格的正例、反例和结构保护标注；
6. LF、CRLF、页眉页脚、连字符断词和 Unicode 组合字符样本。

每条样本需要记录来源类型、是否多栏、人工期望、允许的改写范围和失败原因；原始文件不入库，未经许可的用户文档、截图和日志不得提交。

## 5. 当前决定

- 不引入 PDF/CAJ 解析依赖；
- 不在当前版本加入全文换行替换或无边界 CJK 空格删除；当前仅保留默认关闭的 Han-Han 单 ASCII 空格保守试实现；
- 不把合成基线标记为真实语料通过；
- 保持路线图待办，直到真实语料和失败基线齐备；
- 若后续实现，优先以两个独立、默认关闭的规则进入 `RulePhase::Cleanup`，并复用现有 span/TextEdit 管线。
