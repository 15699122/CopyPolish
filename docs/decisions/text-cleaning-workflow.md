# 文本清洗与规范排版工作流决策

> **状态**：Accepted（规划基线，2026-09-01）。本记录冻结后续文本清洗、字符转换和规范排版功能的边界；其中列出的新功能尚未全部实现。

## 1. 背景

参考 `laorange/paper-assistant` 的产品实践后，确认 CopyPolish 当前能力之外还存在一类实际需求：用户从 PDF、CAJViewer、Zotero、网页或其他来源复制文本后，需要先清理异常空格、断行、引用角标和异常字符，再进行中文规范排版。

CopyPolish 已经具备 Rust 本地引擎、结构 span 保护、Unicode grapheme 边界、规则注册表和 GUI/TUI/CLI 共用管线。后续扩展必须建立在这些边界之上，不能直接复制参考项目的宽泛正则处理器，也不能让低风险排版规则与高风险来源清洗操作混在一个无序处理器数组中。

## 2. 产品边界

CopyPolish 的定位扩展为：

> 本地优先的中文文本清洗与规范排版工具，适用于网页文案、技术文档以及从 PDF、CAJ、Zotero 等来源复制的文本。

当前及规划中的功能分为三层：

1. **文本清洗**：异常空格、重复空行、PDF 段内软换行、引用角标、康熙部首和用户自定义字面量替换；
2. **字符转换**：有限 Unicode 等价字符、全角/半角字符和可选的简繁转换；
3. **规范排版**：中文、英文、数字、单位和标点之间的上下文相关排版规则。

以下能力不属于当前规划范围：

- 直接解析 PDF、DOCX 或其他文件格式；首版只处理用户输入或文本文件中的文本；
- 翻译、LLM 写作、AI 语法改写或 Grammarly 集成；
- 复制参考仓库的 AGPL-3.0 源码、正则表或组件实现；
- 允许用户任意重排核心排版阶段。

## 3. 工作流模型

目标数据流为：

```text
输入文本
  → 用户自定义字面量替换
  → 来源文本清洗
  → 可选字符转换
  → 结构/语义 span 扫描与保护
  → 中文规范排版
  → 最终清理
  → 输出文本
```

其中：

- 自定义替换首版仅支持字面量，不支持用户正则；
- 来源文本清洗必须优先遵守“宁漏清洗、不破坏结构”；
- 字符转换不能默认使用全文 NFKC；
- 简体→繁体与繁体→简体是互斥模式，不是两个可同时勾选的布尔规则；
- Markdown、HTML、LaTeX、URL、邮箱、代码和化学式的保护边界继续由 Rust span 管线负责。

## 4. 执行顺序与配置边界

核心排版规则继续由 `RulePhase`、`before` / `after` 依赖和注册表决定。用户可以启用或停用规则，但不能任意打乱核心阶段，否则可能破坏保护、依赖、幂等性和已有输出兼容性。

未来允许配置的内容：

- 清洗规则的启停；
- 清洗、排版和技术文档等预设；
- 自定义字面量替换项及其列表顺序；
- 实时或手动输出模式；
- GUI 布局和复制后的显式动作。

未来不允许的默认行为：

- 窗口失焦时自动复制或清空用户内容；
- 对全文执行无上下文的换行替换、Unicode NFKC 或标点互转；
- 通过两个独立开关同时启用相反方向的简繁转换；
- 用浏览器 fallback 代替 Rust 引擎行为。

## 5. 实现约束

1. 新规则必须继续加入 `src-tauri/src/engine/registry.rs`，拥有稳定 key、阶段、依赖、默认状态、风险说明和测试；
2. 需要运行时参数的自定义替换、预设和转换模式应扩展 `FormatRequest` 或独立配置模型，不伪装成静态 `RuleDef`；
3. 新清洗规则默认只处理可编辑文本，除非经过独立设计和 fixture 验证；
4. GUI、TUI 和非交互 CLI 必须共享 Rust 清洗与排版语义；
5. 设置新增字段必须使用 serde 默认值，旧版 `rules.yaml` 读取后保持现有行为；
6. 每项高风险清洗能力必须有真实来源语料、保护边界、幂等性、换行风格和失败案例测试；
7. 新依赖先做 Spike，确认许可证、跨平台构建、性能和维护状态后再引入。

## 6. 参考功能的取舍

参考项目中的以下能力适合转化为 CopyPolish 需求：引用角标清理、来源文本空白清洗、康熙部首修复、自定义替换、预设、手动输出和统计信息。

以下实现方式不直接采用：

- 用无结构全文正则处理 Markdown/LaTeX 文本；
- 用任意拖拽顺序替代规则依赖图；
- 用 `blur` 事件触发自动复制和自动清空；
- 依赖 Grammarly 或在线服务完成核心功能；
- 引入全局状态库来替代当前已经验证的 hook 编排和 Rust 设置模型。

## 7. 重新评估条件

当以下任一条件成立时，重新评估本决策：

- 清洗阶段占用端到端处理时间的主要部分；
- 保护 span 与清洗阶段出现无法通过局部规则解决的冲突；
- 简繁转换需要词汇级、地区级语义转换；
- 用户明确需要直接导入 PDF/DOCX，并且愿意接受新的解析依赖和许可证审查；
- TUI/CLI 与 GUI 的配置模型出现无法继续兼容的分歧。
