# 设置存储策略决策（ADR）

> **状态**：Accepted（2026-09-01 维护者确认采纳方案 B，并已按实施约束落地）。
> 背景与相关约束见 [architecture.md](../architecture.md) §5 与 [roadmap.md](../roadmap.md)。

## 1. 问题

当前用户设置 `rules.yaml` 固定保存在**可执行文件同目录**（便携模式）：

- 优点：绿色便携，U 盘/多目录部署各自独立，符合 README 的便携版定位；
- 问题：程序放在只读目录（如 `Program Files`、`/usr/bin`）或安装到系统目录时无法保存设置；安装器类分发形态出现时矛盾会更明显。

现有缓解：只读目录时 UI 显示保存失败提示，文档建议解压到有写权限的目录。

## 2. 候选方案

| 方案 | 行为 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A. 维持纯便携 | 永远 exe 同目录 | 行为不变、零迁移成本 | 只读目录下设置不可用 |
| B. 便携优先 + 应用数据目录回退 | exe 目录可写 → 同目录；否则回退平台应用数据目录（Windows `%APPDATA%`、Linux `~/.config`） | 兼容现有便携用户；只读环境可用 | 回退位置对用户不直观，需 UI 展示实际路径；两位置并存时需明确优先级 |
| C. `portable.flag` 显式标记 | 存在标记文件 → 同目录；默认应用数据目录 | 语义清晰，适合安装器分发 | 破坏现有便携版"开箱即用同目录"行为，需要迁移 |

## 3. 建议（Proposed）

**采纳方案 B（便携优先 + 应用数据目录回退）**，理由：

1. 保持现有便携用户行为完全不变（零迁移）；
2. 只读目录从"功能不可用"变为"自动降级可用"；
3. 不需要用户干预（对比方案 C）；
4. 与现有损坏提示机制兼容：设置路径本就通过 `get_settings_path` 展示，只需同步展示回退路径。

### 实施约束（确认后生效）

1. 解析优先级固定：exe 同目录 `rules.yaml` 存在 → 继续使用；不存在且 exe 目录不可写 → 应用数据目录；两处均无 → 按可写性选择并记录；
2. `get_settings_path` 与设置窗口 Footer 必须展示最终生效路径，回退时在主界面提示"已使用应用数据目录保存设置"；
3. 每次启动只读一次路径决策并缓存，不在保存时改变位置；
4. TUI 与 GUI 必须使用同一决策逻辑（复用 `user_settings.rs`，不复制）；
5. 损坏恢复（`.bak`）、legacy JSON 迁移在两个位置语义一致；
6. 设置读写测试补充：只读目录回退、同目录优先、双位置并存三个用例；
7. CHANGELOG 记录用户可见变化；README 的"用户设置"章节同步。

### 重新评估条件

- 出现安装器/包管理器分发形态；
- 需要按用户（而非按程序目录）隔离设置；
- 用户反馈回退位置难以发现。
